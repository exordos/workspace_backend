# Messenger 退缩测试计划

这个计划验证PostgreSQL是正规Messenger存储,而
目前浏览器面向的 API 和 S3 文件行为保持不变.
也定义重建,恢复,规模和负载接受.

## 接受规则

- REST路径,请求和响应体,状态码,排列,过器
  视力规则,事件有效负载与确定的 Messenger
  基线
- `/api/workspace/v1/messenger/**` 仍然是公共 Messenger REST 命名空间;
  旧的`/api/messenger/**`路径仍然不存在.
- REST 和websocket事件在JSON解码后等于,并且仍然被范围
  认证的 IAM 用户和项目.
- PostgreSQL 存储正规的 Messenger 资源,状态,事件和提供商
  运行时读写不使用 SMTP, IMAP,Maildir,Exim,或
  子.
- 文件,元数据侧车和二进制访问继续使用S3兼容
  信息只包含授权的URN.
- 提供者运行时通过常规Messenger资源和命令交换
  私人 Workspace 提供商 API 并永远不要连接到 Workspace
  没有数据库.
- 只有为配置的间隔保留事件记录,
  默认. 消息,文件,流,主题,设置和提供商映射
  它们的正常生命周期将会被删除.

## 测试环境

- 隔离 Workspace 后端,新鲜的 PostgreSQL 数据库和所有
  它们的迁移.
- 专用于测试运行的 S3 兼容物体存储.
- 两个 IAM用户在一个项目和一个 IAM用户在另一个项目
  最低功能的运行;全负荷配置文件定义在 PostgreSQL
  规范性计划.
- 一个独立部署的 Zulip 提供者运行时间和一个专用 Zulip
  提供者场景的测试领域.
- 一个可见的全球剧作家 MCP窗口使用真实的 `cassi`帐户
  显著的接受.

## 执行命令

1. 运行未改变的 Messenger 单元和集成套件.
2. 运行路由, OpenAPI, IAM,事件,提供者 API,和 S3合同测试.
3. 应用不可变的后端更新,同时保留PostgreSQL和S3数据.
4. 执行 Messenger API,提供者,存储,重新启动,重建,故障,以及
   隔离情况.
5. 在可见的全球剧作家 MCP 浏览器中执行支持的行程.
6. 执行150个同时用户负载和提供商工作负载.
7. 保存清洁的证据在CASSI测试运行档案中.

只有当所有所需的情景都通过时,才能接受运行.
执行的值是 `NOT RUN` 或 `BLOCKED`;不应报告为已验证
它们的相容性.
