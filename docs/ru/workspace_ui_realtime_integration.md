# Workspace Интеграция пользовательского интерфейса в режиме реального времени

В этом документе описывается общественный Messenger контракт в реальном времени, потребляемый
Workspace Интерфейс пользователя. REST догонка и доставка веб-сокета используют одно и то же плоское событие
объекта и те же правила видимости с охватом IAM.

## Конечные показатели

- `GET /api/workspace/v1/events/`
- `GET /api/workspace/v1/epoch/`
- `WS /api/workspace/v1/events/ws?last_epoch_version=<number>&epoch_generation=<generation>`

Внутренний путь службы веб-сокета `/v1/events/ws` на `127.0.0.1:21082`.
Код браузера должен использовать только путь nginx выше.
или внешнеинтегрируемые конечные точки веб-сокетов.

| Транспорт | Аутентификация | Заказ | Предназначенное применение |
| --- | --- | --- | --- |
| `GET /events/` | IAM заголовок носителя | восходящий `epoch_version` | Начальная нагрузка, восстановление связи, улаживание разрыва |
| `GET /epoch/` | IAM заголовок носителя | один последний курсор | Сравните локальное продвижение с видимой эпохой сервера |
| `WS /events/ws` | IAM токен в подпротоколе | Пропущенные ряды, затем живые ряды | Доставка с низкой задержкой после догоняния |

## Аутентификация

REST запросы используют IAM носитель токен:

```http
Authorization: Bearer <accessToken>
```

Клиенты веб-сокетов отправляют точно эти два значения `Sec-WebSocket-Protocol`:

```ts
["workspace.events.v1", `bearer.${accessToken}`];
```

Сервер выбирает `workspace.events.v1`. Не вставляйте токен в запрос
Настойчивость и отправка `epoch_generation` с каждым курсором продолжения, не относящимся к нулю;
Опущенный `last_epoch_version` означает холодный курсор `0`.
требуют поколения, но он возвращает нормальный типированный ответ разрыва, когда
конфигурированный заполненный суффикс, по умолчанию 72 часа, не может обеспечить полную
История с эпохи `1`.
Неавторизованное рукопожатие с `4401` и недействительное рукопожатие с `4401`

## Форма события

Каждое событие REST и сообщение события веб-сокета одинаковы `schema_version: 1`
Объект. нет внешней обертки `{ "type": "event", "event": ... }`.
Socket дополнительно отправляет сообщения о вводе `ready` и ошибке курсора.

```json
{
  "schema_version": 1,
  "uuid": "event-uuid",
  "epoch_version": 124,
  "project_id": "project-uuid",
  "user_uuid": "recipient-user-uuid",
  "object_type": "message",
  "action": "created",
  "created_at": "2026-07-02T16:37:49.552044Z",
  "updated_at": "2026-07-02T16:37:49.552047Z",
  "payload": {
    "kind": "message.created",
    "uuid": "message-uuid",
    "project_id": "project-uuid",
    "user_uuid": "recipient-user-uuid",
    "stream_uuid": "stream-uuid",
    "topic_uuid": "topic-uuid",
    "author_uuid": "author-user-uuid",
    "payload": {
      "kind": "markdown",
      "content": "Hello"
    },
    "read": true,
    "pinned": false,
    "starred": false,
    "is_own": true,
    "reactions": {},
    "reaction_users": {},
    "created_at": "2026-07-02T16:37:49.552044Z",
    "updated_at": "2026-07-02T16:37:49.552047Z"
  }
}
```

Поля верхнего уровня описывают ряд событий.
`payload`, и `payload.kind` является единственным `kind` полем на полезной нагрузке события.
Представительство локальной стойкости является внутренней деталью и никогда не
Появляется в форме общественного мероприятия.

Создание, обновление, чтение и действия событий несут тот же полный объект снимка как
соответствующий ответ Messenger REST, плюс `payload.kind`.
события минимальны:

- `stream.deleted`, `folder.deleted` и `folder_item.deleted`: `kind`, `uuid`;
- `topic.deleted`: `kind`, `uuid`, `stream_uuid`;
- `message.deleted`: `kind`, `uuid`, `stream_uuid`, `topic_uuid`,
  `author_uuid`, `source_name` и `source`.

Изменения реакции излучают `message_reaction.created`,
`message_reaction.updated`, или `message_reaction.deleted` для действующего пользователя.
Задней панель также излучает `message.updated` снимки с обновленным агрегатом
`reactions` карта и постоянная ограниченная `reaction_users` карта для пользователей, которые могут видеть
Каждый присутствующий ключ `reaction_users` представляет собой полный список пользователей UUID
Клиент заменяет всю карту на
каждый полный снимок сообщения; пустой объект или отсутствующий ключ означает только подсчет
и должен удалить любой ранее кэшированный список.

Создание бачных потоков связывания использует `payload.items`.
`message.read`, `topic.read` или `stream.read` и продолжают выделять агрегат
`topic.updated`, `stream.updated` и `folder.updated` события, когда они нечитаются
Перемены в счетчиках.`messages.read`с
`message_uuids`.

Поддерживаемые значения:

| `object_type` | действия |
| --- | --- |
| `message` | `created`, `updated`, `deleted`, `read` |
| `message_reaction` | `created`, `updated`, `deleted` |
| `stream` | `created`, `updated`, `deleted`, `read` |
| `stream_binding` | `created`, `updated`, `deleted` |
| `topic` | `created`, `updated`, `deleted`, `read` |
| `user` | `updated` |
| `folder` | `created`, `updated`, `deleted` |
| `folder_item` | `deleted` |
| `file` | `created`, `updated`, `deleted` |

## Достижение и обработка курсора

Запрос событий, строго новейших, чем последняя успешно примененная эпоха:

```http
GET /api/workspace/v1/events/?epoch_version%3E=<last_epoch_version>&epoch_generation=<generation>&page_limit=500
```

`epoch_version>` строго. Процесс событий в восходящем порядке и сохранять
курсор только после применения события к каждому затронутому магазину клиента.

`GET /api/workspace/v1/epoch/` возвращает поколение, текущую эпоху и
удерживающий пол, видимый текущим пользователем IAM и проектом:

```json
{
  "epoch_version": 124,
  "epoch_generation": "781203",
  "current_epoch_version": 124,
  "minimum_epoch_version": 37
}
```

Правила курсора:

- обращаться с `(epoch_generation, epoch_version)` как с одним неделимым курсором и отправлять
  генерация с каждым не нулевым REST или websocket resume;
- игнорировать события, эпоха которых меньше или равна заданному курсору;
- исправлять пробел с REST догоняющим, вместо того чтобы догадываться о состоянии ресурса;
- разделение или счистка курсора при изменении пользователя или проекта IAM;
- никогда не в порядке события UUID или часовой метки;
- Перенаправлять страницу до тех пор, пока сервер не вернет никакого дополнительного маркера страницы.
- обрабатывать HTTP 410 `EventsCursorExpiredError` / `error=epoch_pruned` как кэш
  перезагрузить границу; обновлять авторитетные снимки и перезагрузить с возвращенной
  Сервер сохраняет события на конфигурируемый интервал, 72 часа
  по умолчанию, и это сброс никогда не удаляет сообщения, файлы или состояние домена.

## Доставка веб-сокета

После принятия соединения, сервер отправляет пропущенные события более поздние, чем
сохраненный курсор, затем отправляет
`{"type":"ready","epoch_generation":"...","epoch_version":124}`.
Событие может обогнать этот кадр.
`ready`; сообщения догнания должны обновлять состояние без уведомления.
фремы управления ping-управлением веб-сокета, не применяемые для JSON `hello`, `ping`, `pong` или
`ack` сообщения. Исходящий курсор отправляет тело введенной ошибки и закрывается с `4410`.

Рекомендуемый поток клиентов:

1. Загрузить пару с обязательным курсором или использовать холодную эпоху `0` без поколения.
2. Запустить REST догнать до тех пор, пока больше не будет возвращено событий.
3. Откройте веб-сокет с последней парой курсоров.
4. Применение сообщений REST и websocket через один и тот же диспетчер.
5. Сохраните уведомления отключенными до того момента, пока не будет установлен фрейм websocket `ready`, затем включите
   уведомления в режиме реального времени.
6. Дедуплировать на `(epoch_generation, epoch_version)`.
7. После закрытия, снова запустите догонять и снова подключить с задней стороны.

Фаза пропущенного события веб-сокета закрывает гонку между последней страницей REST и
Дедупликация по-прежнему обязательна, потому что неоднозначные сбои могут
воспроизвести уже примененное событие.

## Отправка ВИ

Первое отправление - по верхнему уровню `object_type` и `action`, затем по `payload.kind`
Неизвестные версии схемы или события
значения должны регистрироваться и перескакиваться без нарушения цикла реального времени.

| `object_type` | Первичное хранилище или эффект пользовательского интерфейса |
| --- | --- |
| `message`, `message_reaction` | Временная линия, реакции, нечитаемое состояние |
| `stream`, `stream_binding`, `topic` | Навигация, членство, состояние темы |
| `folder`, `folder_item` | Навигация папок и значки |
| `user` | Общий кэш идентификации и присутствия |
| `file` | Метаданные файлов и защищенный/public блок-кеша |

`stream.deleted` для удаленного участника отменяет весь поток: выселить
все защищенные точки, в кэше которых метаданные имеют этот `stream_uuid` немедленно.
Остальные члены получают `stream_binding.deleted`; обязательные изменения производят
`stream_binding.updated`. Ошибка пробела курсора убирает все полученные защищенные пятна
Кэшируются перед перезагрузкой снимков.

Содержание сообщения V1 использует форму "уменьшенная полезная нагрузка":

```json
{ "kind": "markdown", "content": "Hello" }
```

Присутствие обновляется через REST
`users/{uuid}/actions/presence/invoke` действие. Работник отмечает устаревших пользователей
Онлайн и передает `user.updated` с полным публичным снимком пользователя.
